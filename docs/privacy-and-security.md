# Privacy and security

- Android voice uses the user's own Groq, Gemini, and OpenRouter keys directly; keys are not embedded in builds. Any managed backend keys remain in backend secret storage and are not copied to the phone.
- Android installation refresh credentials and BYOK values use Keystore-backed encrypted preferences.
- Android sends keys only to their matching official provider over HTTPS/WSS. Redirects are disabled. Capacitor bridge logging is disabled so key-entry arguments are not logged.
- Android audio is buffered only in request memory and released on finish/cancel/error. No audio files are written by the direct voice transport.
- Transcript history remains in the device Room database. Server conversation history does not exist.
- Voice AI preserves an explicit selection or selects the whole field when none was chosen, then sends that selected text (up to 20,000 UTF-16 units) to Gemini/OpenRouter alongside the spoken instruction. No other surrounding document text is requested; selection context is not sent to Groq, logged, or stored in history as a separate field. Raw and Live do not capture target-app context.
- Text polish is a separate, explicit IME action: with a nonempty selection, only that exact substring is sent to OpenRouter and targeted for replacement; without a selection, the whole eligible field is used. Complete-field guard reads (at most 20,000 UTF-16 units) are transient and local even for selected-text Polish; surrounding text is neither sent with a selected-only request nor logged or persisted. Protected, partial, styled, oversized, and unreadable fields are refused before transmission. Session, connection, text, selection, and operation checks guard replacement. Completed corrections that cannot be safely applied or verified have in-memory Copy/dismiss recovery for up to 120 seconds, not automatic persistent Polish history; copying explicitly writes the system clipboard. The optional polish system prompt is stored locally in DataStore and sent only on a tap. Ordinary typing makes no external request. Provider edits, including changes to proper names, still require review.
- The optional AI system prompt is stored locally in DataStore and sent only with AI answer requests. Blank restores the default. Selection and prompt limits are 20,000 and 8,000 UTF-16 code units respectively. History still stores the resulting output and spoken transcript, which can naturally contain excerpts from selected text.
- Logs exclude bodies, audio, transcripts, prompts, context, access/refresh tokens, and credentials. Operational fields are request ID, status, latency, provider/model, retry count, and metered units.

Android refuses voice input in password, phone, numeric/payment-like, and no-personalized-learning fields. The floating control remains visible but cannot start a request there. Because Android does not reliably identify payment semantics through `EditorInfo`, all numeric input classes are conservatively blocked. The published store build additionally allows ordinary typing in numeric and phone fields, so a user can still enter their own account number, but emoji and the clipboard are refused there and everywhere a password variation or `IME_FLAG_NO_PERSONALIZED_LEARNING` is present.

## Local clipboard and editor reads

Automatic clipboard capture is enabled by the versioned migration for this update; subsequent explicit opt-outs are preserved. The panel's **Save copied text automatically** switch disables capture. A lifecycle-owned listener samples only while Odicto is the default IME, the editor is eligible, and Android allows access, including while the panel is closed. It unregisters when no longer eligible. Protected fields are excluded and clips marked `android.content.extra.IS_SENSITIVE` are skipped; unmarked secrets cannot reliably be detected. Capture is best effort, not a historical stream or a promise to recover copies missed while stopped or inaccessible.

`ClipboardRepository` retains 50 distinct unpinned recent entries plus persistent pins in versioned JSON DataStore under `noBackupFilesDir/clipboard/history-v1.json`, separate from voice settings. Exact plain text, whitespace, newlines, and Unicode survive storage and paste; ellipsis is preview-only, and URI/file contents are not coerced into text. Identical copies move to the front. Pins have no five-item eviction limit and survive bulk deletion and Clear all unpinned until explicitly unpinned. Clipboard content is local, excluded from backup, logs, and network. Explicitly copying a completed result can also place it in this history when capture is eligible.

Migration preserves recoverable legacy entries and pins and cleans up legacy settings only after the new-store transaction. Previously truncated or delimiter-corrupted text cannot be reconstructed. Rendering reads saved state, not `ClipboardManager`. Deletion/clear retains a capture token so an unchanged system clip is not restored on recreation; a genuine later copy may add it again. Clearing saved history does not clear the system clipboard, and disabling capture does not erase existing history.

Emoji are a fixed local Unicode set committed with `commitText`; nothing is downloaded and no provider is contacted. The five pinned emoji remain separate from clipboard pins. Cursor movement uses transient local editor text and is disabled during voice/AI selection work. Live composing reads its own preceding output and selection locally for consistency checks, not as provider context. Native dictation treats API acceptance as unverified delivery, offers explicit Copy and device-only voice history recovery, and never automatically repeats ambiguous insertion or the provider request. “Saved to history” appears only after persistence succeeds.

Manual typing assistance and held deletion use transient, local bounded suffix reads (up to 96 UTF-16 units) in eligible fields. Observed/predicted session state and a bounded edit ledger reconcile delayed/coalesced host evidence; they are neither provider context nor persistent history. Refreshes occur at context/credit boundaries rather than on every trusted repeat. Unknown selection metadata may fall back to readable suffix evidence without inventing cursor zero. Missing, partial, or ambiguous evidence is not empty text or proof of an applied edit: destructive repeats wait and may resume within the same valid hold. Opaque/protected hosts may exhaust the evidence allowance; protected-field no-read rules and manual taps remain. See [Manual input continuity](architecture.md#manual-input-continuity) for bounds and integration limitations.

Keyboard diagnostics are debug/test-only and content-free: bounded timing samples and aggregate counts exclude text, key values/labels, prompts, clipboard payloads, and credentials. The standalone permissionless `tools/keyboard-interaction-host/` (`app.odicto.keyboardtrial`) uses generated in-memory text, disables backup/text persistence, and has no network, microphone, contacts, or storage permissions or clipboard integration. Its instrumentation targets only the disposable host, never personal Odicto storage. API return, host text change/draw, screen presentation, and physical vibration onset are distinct endpoints; see [Current trace — debug-only, content-free](android-development.md#current-trace--debug-only-content-free). Never inspect saved keys or personal app data to collect measurements.

The optional AccessibilityService in the legacy flavor resolves the edited field from the window that holds input focus, which also covers apps that keep the field in a second window (Chrome and other WebView surfaces). It reads only that focused window's root, and only to locate the focused field for insertion; it never walks other windows, navigates, or collects content. Audio is captured from the moment a request starts so the first words are not lost, buffered in memory until the provider connection is ready, and discarded with the session if it ends first; it is never written to disk. Pausing from the app or the Quick Settings tile stops the overlay and disables the accessibility service, which is exactly what protected apps check; Android requires the user to turn that service back on from Settings, so resuming opens that screen.

Play disclosures for the published store build cover the microphone foreground service, network processing by the selected AI providers, device-only history, and optional BYOK. The store build ships no AccessibilityService and requests no overlay permission, so neither appears in its manifest. The legacy flavor's disclosures additionally cover the `specialUse` foreground overlay and the narrow accessibility service.

Android does not clear a previously enabled accessibility service when an app update removes it. If a user ever moves from the legacy flavor to a differently signed build, the old install must be removed manually and the stale service switched off in system settings. This is a known future migration concern for a Play release; it is not surfaced in the app today, because Play distribution is not current.

On iOS, Odicto will not claim a floating microphone or microphone access from a custom keyboard. The planned experience is an in-app recorder plus an AI keyboard that transforms text entered through Apple dictation.
