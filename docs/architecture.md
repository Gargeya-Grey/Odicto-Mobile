# Architecture

## Runtime flow

Android IME/overlay -> AudioCaptureService -> direct external provider APIs -> session-checked InputConnection insertion.

- Raw: recorded PCM is compressed in memory to lossless FLAC as it arrives and sent directly to Groq Whisper after release; nothing is sent before release.
- AI: Groq transcribes speech, then Gemini or OpenRouter receives the spoken instruction, any explicitly selected text, and the device-saved custom system prompt (or the default when blank).
- Live: PCM streams directly to Gemini Live; provisional words update one native composing range in the original editor. Finalization finishes composition without pasting a second copy. Cursor/content verification prevents subsequent writes after the target changes. Cancel/error retains already typed words.
- Text polish: an explicit IME tap sends only the selected substring, or the whole field when the selection is empty, to the separately selected Gemini or OpenRouter provider with its polish model/prompt. Complete-field reads are transient local guards; only the captured target range is replaced after revalidation. Typing alone makes no provider request.

Provider calls run in Kotlin. User API keys are stored in Android Keystore-backed encrypted preferences and used only with the selected provider. There is no local model, PC service, installation-token exchange, or Odicto gateway in the Android voice path. Modes are selected before recording.

Opening a Gemini model menu explicitly requests Google's model catalog through the native bridge using the saved Gemini key. The UI merges the returned content-generation candidates with bundled fallback choices; catalog metadata does not prove billing eligibility, quota, or inference access.

The toolbar Undo delegates to the focused host's edit history with one Ctrl+Z key-down/key-up pair through its current input connection. It covers the edits that host records, including typing, backspace, paste, selected-text deletion, voice and Polish, in the host's own order. It is available independently of Polish's local verification stack; Android has no universal cross-app `canUndo`. An accepted shortcut is never followed automatically by a native menu command or a local Polish replacement. Apps that ignore the shortcut or have no history can leave the field unchanged, which Odicto reports without claiming success. `EditorUndoCoordinator` rechecks editor epoch, connection and policy for dispatch and bounded confirmation; new typing, voice, Polish or editor lifecycle changes cancel pending feedback. Only an explicit Undo tap can read an eligible complete text snapshot for transient before/after confirmation. Opaque and Odicto-owned editors, numeric and phone fields use the shortcut without text reads or local edit history. Password and no-personalized-learning fields refuse Undo. Host support still needs real-device verification.

React/Capacitor hosts settings and onboarding. Native Kotlin owns recording, provider transport, editor policy, and insertion. The retained Fastify workspace serves the separate web/backend implementation; Android voice does not call it.

## Earlier backend design (not used by Android voice)

The production target is a Node 22 Fastify container on Google Cloud Run, Supabase Pro Postgres, Upstash Redis, and RevenueCat. Cloud Run supplies managed autoscaling, spend caps, integrated observability, and a published runtime SLA. Supabase is the affordable managed Postgres/account layer; database access stays standard and portable because Supabase Pro itself has no contractual uptime SLA.

Postgres is authoritative for installation credentials, idempotent operations, quota, usage, and entitlements. Redis provides short-window installation/IP rate limits only. RevenueCat verifies Play purchases and sends idempotently processed entitlement events.

## Native safety model

`DictationCoordinator` binds recording, processing, and delivery to an operation ID, monotonic editor-session ID, target/connection identity, and selection version. `EditorPolicy` is rechecked before insertion; stale targets are rejected. `DeliveryOutcome` separates `CONFIRMED`, `ACCEPTED_UNVERIFIED`, and `REJECTED_STALE`. The current native targets conservatively map successful Android API calls to accepted-but-unverified, not proof of visible insertion, including Live finalization. Provider completion and history persistence are separate: `VoiceSession` reports Saved only after the Room write succeeds, guards late callbacks by result ID, and keeps failed/unverified results available for explicit Copy rather than expiring them as insertion success. No automatic insertion or provider retry occurs; users should inspect the field before pasting to avoid duplicates.

`KeyboardStatusPresentation` owns only the IME's one-line feedback and monotonic deadlines. It keys voice feedback by operation/result/phase, so meter and history callbacks cannot renew a terminal deadline; newer Polish/Copy notices suppress old voice feedback. Lifecycle changes remove view timers without clearing results or replaying expired messages. Busy feedback has no timeout; terminal feedback defaults to three seconds with the platform accessibility extension. Nine fixed toolbar allocations (keyboard toggle, Undo, six voice cells, and Polish), a permanent quick-edit row of comma/period/space/backspace/enter below them (see [Android development](android-development.md)), and a compact Polish recovery card in the existing content slot preserve the fixed IME window geometry. Recovery reveals only the measured card height, keeps its explanation beside Copy/Dismiss, and restores the previous typing presentation when closed. It has no visible countdown or per-second view timer. The 120-second Polish recovery lifetime and persistent unverified voice recovery remain distinct and unchanged.

Failures and notices reset themselves. `VoiceSession` clears an error or notice 5 seconds after it appears (longer when Android's accessibility timeout asks for more), keeping any retained result text for Copy and only dropping the message. A newer state, or a newer error with its own timer, is never touched by an older timer. The overlay card's deadline matches that lifetime, so the card and the stored message end together and a later double tap can no longer reopen a stale error. The card prints a message once: with the preview on, an explanation fills the preview line and the caption above it stays empty.

The floating microphone never moves for anything else. `OverlayGeometry` and `VoiceControlView.render` size the window around the microphone, never the reverse: every piece (options row, recording controls, message card) is placed relative to the microphone's left edge, the window is the bounding box of what is placed, and the view reports the microphone's offset inside that box so `VoiceOverlayService` positions the window with the microphone exactly on its anchor. Controls reaching beside the microphone open toward the side that has room (keeping the current side when both fit); when neither side fits, the full options row stacks on a row above the microphone, with the button pitch tightened on very narrow screens. The message card is independent of the microphone horizontally and slides to stay on screen, never wider than the screen allows. `OverlayLayoutSweepTest` checks, across screen widths, microphone positions and every content state, that the microphone is drawn at its offset, every piece and the window lie on screen, and no two touch targets overlap. A drag first folds an open card away (a retained result stays reopenable with a double tap), starting from where the microphone is drawn. The microphone is placed from the finger's total travel since the touch went down (including the point where it lifted), not from accumulated steps, so it stays exactly the grabbed distance from the finger, with no lag behind the touch slop and no drift after an edge clamp; a gesture cancelled mid-drag still saves where the microphone was left. The microphone can go anywhere on screen, flush to either side: the window uses `FLAG_LAYOUT_NO_LIMITS` so its empty margin may hang past the screen, and the microphone asks the system (`systemGestureExclusionRects`, Android 10+) to leave swipes that start on it alone instead of reading them as Back. Below Android 10 there is no gesture strip to avoid. Its place is stored as a share in millionths (0..1,000,000; `OverlayGeometry.shareOf`/`valueAt` round-trip every pixel exactly) of the screen's width and of its height without the keyboard (`anchorX`/`anchorY`; older thousandths values are scaled up, with the pixel position kept only as a fallback), and is turned back into pixels whenever the screen's size or density changes, so it survives rotation, display-size changes and unfolding; a sideways drag never alters the saved vertical place. The overlay is forced left-to-right so a right-to-left locale does not mirror it, and its view is rebuilt in place when the font or display size changes; card text follows the font size only up to 1.3x so the fixed-height card cannot clip. The idle bubble wears the Odicto logo mark (`odicto_ic_logo`, five white strokes tinted from the palette like every other icon) instead of a microphone; recording shows the stop glyph, and the keyboard header keeps its own microphone button. The mark is wider than tall, so it is drawn at 29% of the disc rather than the 21% the line icons use.

`OverlayPresentation` separately owns the floating control's process-local presentation deadline. The options row (opened by a double tap) and the last result it brings along fold away after about eight seconds without a touch (a touch restarts that time; opening them again brings them back). It is as tall as the microphone and ends exactly at its far edge, concentric with the disc. It opens out of the microphone: the body grows outward from the disc's centre with half-circle ends at every size (`PillView.reveal`), rising out from behind the disc when it opens above it, and the five controls slide out from the centre nearest-first, while the microphone itself never moves (the window's margins are identical in every state and each piece is placed from the window edge that stays a fixed distance from the disc; a per-frame log of the open showed the window and disc constant apart from the tap's own press-shrink easing back); while it is open a mic with no field is dimmed by colour, not alpha, so the pill does not show through. Terminal chrome collapses to the 72dp mic surface after three seconds, extended by Android's accessibility timeout, without clearing the retained result. Back collapses only presentation; the existing double-tap/options action reopens Copy and mode controls, including for Live output. History/meter updates do not renew the deadline; hidden/recreated views do not replay expired results. A new busy phase supersedes the old timer. Copy revalidates the current eligible target and clipboard failure preserves recovery.

These presentation contracts are separate from acceptance evidence: neither a matching installed APK hash nor a registered IME proves stable on-screen geometry or successful insertion. See the [bounded status verification handoff](s24-ultra-testing.md#keyboard-status-fix-bounded-verification-handoff) for observed checks and remaining physical coverage.

The keyboard microphone and the optional overlay remain visible together and call the same recording service/state machine; the existing busy guard prevents concurrent recordings. The IME publishes only its top-edge screen coordinate so the overlay can stay above the typing area. This temporary placement does not rewrite its saved position; the preferred anchor returns when space is available. `DictationCoordinator` routes the finished text to the Odicto IME's `InputConnection` while Odicto is the active keyboard. The Odicto IME is the only insertion channel: the build ships no accessibility service, because Play Protect blocks sideloaded installs that declare it. The in-app pause switch and the Quick Settings pause tile stop the overlay, which is the documented answer for protected apps that refuse to run beneath an overlay.

The Odicto IME opens each editor with its voice bar only. The top-left keyboard button expands or collapses the typing area by sliding it (instant when system animations are disabled); the IME window keeps one height and reports its visible top through `onComputeInsets`. This presentation state is session-local and never detaches the editor or changes dictation routing. The expanded keyboard provides letters, shift, numbers, symbols, emoji, a locally retained clipboard panel, and a spacebar that types a space on a tap or moves the cursor horizontally when armed. Both symbol pages retain five rows; the number page includes straight quotes and common ASCII punctuation, and the symbol page includes braces, backslash, typographic quotes, currency, bullets, and arrows. The emoji picker offers 608 local choices across nine scrolling categories and stays on the current category and scroll position after insertion. Recent choices are filled out to 32 with local defaults. Polish recovery temporarily reveals its compact Copy/Dismiss card, without expanding the key grid, and remembers whether typing was collapsed or expanded. `SpaceGesture` decides the gesture without Android types, `CursorNavigator` computes the new selection over grapheme clusters, and `KeyboardController` is the single place that writes to the editor. Cursor gestures are refused while a voice request is running or an AI selection is captured, so they cannot invalidate a pending rewrite or a Live composing range. `EditorPolicy` keeps separate answers for manual typing, dictation, emoji, and clipboard: typing works in numeric and phone fields, while everything that reads or writes on the user's behalf stays out of password and no-personalized-learning fields.

`FieldPolishSnapshotReader` verifies complete text against the text before, inside, and after the selection without changing it; partial, styled, oversized, protected, or unreadable fields are refused even for a short selection. `FieldPolishSnapshot` separates complete guard text from the normalized target range and provider payload. `FieldPolishCoordinator` cancels on typing, selection, focus, or voice changes and rechecks session, connection, complete text, selection, and generation before a bounded replacement. A selected operation preserves surrounding text and selects the replacement (including reversed selection direction); whole-field operations map the cursor. Readback must match the expected text exactly, with one bounded rich-editor exception: when the original field ended in LF and the replacement reached its end, the host may recreate that one final paragraph marker. No other whitespace or content is normalized. The actual verified field and selection are used for Undo; Undo on this host sends the original content without duplicating the host-created marker and refuses if the field changed. After an accepted write, confirmation may re-read for up to 160 ms to let an asynchronous host publish its buffer, rechecking operation, editor session, connection and policy on every read. It never repeats the write or provider call, and a cursor moved during that wait is left alone. Post-commit verification distinguishes applied text from unverified delivery. Unapplied/unverified completed results have bounded in-memory Copy/dismiss recovery for 120 seconds, with no automatic retry or persistent Polish history.

Clipboard capture, storage, and rendering are separate: `ClipboardCapture` gates a lifecycle-owned listener; `ClipboardRepository` serializes exact-text mutations and legacy migration in a dedicated versioned DataStore; `ClipboardPanel` renders saved state and exposes capture, pin/unpin, and deletion controls. For eligibility, retention, migration loss, and disclosure requirements, read [Privacy and security](privacy-and-security.md#local-clipboard-and-editor-reads). For precise hit bounds, cursor/hold thresholds, and the width/orientation-aware shared-column split layout, read [Keyboard feel settings](android-development.md#keyboard-feel-settings). Compact keyboard chrome is IME-only. The floating overlay retains its microphone anchor and gestures; its separate terminal presentation now collapses without discarding Copy recovery.

AI captures a request-scoped selection snapshot at recording start, including the cursor when nothing is selected. Before committing, native code checks the original editor, selection range, selected text, and observed selection changes. Changed or unreadable selections fall back to local history/copy without moving the cursor or restoring a stale selection. Android 12+ uses `getSurroundingText(0, 0, 0)` for selection-only snapshots; older Android uses IME selection callbacks with `getSelectedText`. Unsupported or oversized snapshots fail closed. See [Android InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection). Raw and Live do not capture selection context.

Without an accessibility service, a focus the Odicto keyboard does not own has no insertion target: the floating microphone stays on screen, dimmed, and a press explains that voice types through the Odicto keyboard. The overlay is revived after a reboot or an update the next time the app opens or the Odicto keyboard starts input in any field (the accessibility binding used to do this); nothing starts it at boot.

Choosing AI mode pre-selects the whole field so the rewrite target is the entire text; a range the user already picked is left untouched. Tapping a cursor afterwards collapses the selection, and the answer is inserted at that point instead.

Update notification is native and optional. `UpdateChecker` asks GitHub's public release list at most once an hour, when the main app opens, and only while the user's **Check for updates** setting is on. It compares the highest `vMAJOR.MINOR.PATCH` tag with the installed `versionName`; a newer one shows a card at the top of Home. React only presents it: `UpdatePlugin` exposes `status`, `check`, `setEnabled`, `dismiss` and `openDownload`, and the card's **Download** opens the release page in the browser, so installation is always Android's installer acting on an APK signed with the same key. The IME and overlay never make this request. Timing, offer and dismissal rules are pure (`UpdatePolicy`) and tested without a phone; see [Android development](android-development.md) for the full contract.

Light and dark are one setting for every surface. `Appearance` (`system` by default, `light`, `dark`) is stored by `AppearanceStore` in a small SharedPreferences file (the launch screen needs it before any coroutine runs) and written by the web app through the `OdictoAppearance` plugin. `system` follows the phone's day/night setting live. Three consumers read it. The app screens: the header button and the Settings control call the plugin; React shows the theme at once (`data-theme` on `<html>`, tokens in `voice.css`, the last choice cached in `localStorage` so the first paint is right) and the activity follows through `AppCompatDelegate` night mode, which also drives the status/navigation bar icons, the window background and the launch screen's day/night resources. The keyboard and the floating microphone are services, so Android's day/night switching never reaches them and the in-app choice can differ from the phone's: each builds its views from `OdictoTheme.themed(...)`, a context that overrides only the night bit so every `@color` resolves from `values/odicto_colors.xml` (day) or `values-night/odicto_colors.xml` (night), whatever the phone says. Colours live only in those two files with identical names; Kotlin reads them with `getColor` from the view's own context and does not hold literals. A change rebuilds the keyboard in place (`setInputView`) and the overlay view (the same hide/refresh a font-size change uses); the keyboard keeps showing while it happens. `OdictoPaletteTest` checks contrast for every important ink/surface pair in both palettes, and that each theme answers with its own colours even when the phone says the other.

Default prompts and the user's own. AI mode (`DirectVoiceTransport.ANSWER_PROMPT`) and Polish (`FieldPolishClient.DEFAULT_SYSTEM_PROMPT`) each have built-in instructions; Polish also strips fillers, stutters and false starts from raw dictation while keeping wording, tone and language and never censoring. A user prompt is combined by `PromptComposer` according to `PromptMode`: **append** (default) sends our rules first and the user's text after a framing line that says it is notes and cannot change the output rule; **replace** sends only the user's prompt. A blank prompt always means ours. Settings stored before the choice existed keep replacing if they hold a custom prompt (`PromptMode.forStored`). The limit applies to what the user typed, and composition happens at send time, so the request is bigger than 8,000 characters only by our own text. `DefaultPromptsTest` and `PromptComposerTest` pin the rules.

## Manual input continuity

Optional English autocorrect is native and fully on-device. The default-off `KeySettings.autocorrectEnabled` setting crosses the existing React/VoicePlugin settings bridge; no typing reaches an API or system spell-check service. A bundled, attributed 40,000-word frequency list supplies explicit spelling choices off the IME thread. Space applies a confident correction: contractions, a reviewed typo table, or one plausible edit with no close rival, scored by keyboard adjacency and word frequency. Suggestions, completions and Undo share the fixed top row with status feedback while expanded and never add height; the compact voice bar never shows spelling choices. Status temporarily masks suggestions. Pending lookup results cannot revive a cleared or collapsed row. AI Polish remains a separate explicit action with its existing model and prompt.

`SpellingWord` identifies only a bounded current word and editor epoch. Replacement and immediate undo require a fresh matching cursor/range, connection and eligible policy; accepted-but-unverified results are not retried. Backspace or the spelling strip's Undo choice restores the original word without its triggering space; the next Space preserves that choice. Focus/cursor changes, panels, collapse, voice/Polish work and preference disablement discard pending choices and undo. No user dictionary or typed-word history is persisted. Spelling excludes protected fields and identifiers (including email/URI/name fields). `TYPE_TEXT_FLAG_NO_SUGGESTIONS` also excludes spelling except in ordinary text fields with `IME_ACTION_SEARCH`, where the user-enabled local correction takes precedence over the app's candidate-display preference.

These are implementation contracts; replay and physical evidence is recorded separately in [S24 Ultra testing](s24-ultra-testing.md). `KeyboardController` serializes manual writes on the IME thread. Ordinary characters commit immediately relative to the editor, without frame-spanning batches, per-letter selection queries, or speculative absolute cursor repair. Compound mutations such as guarded uppercase replacement use operation-scoped batches closed in `finally`, outside reads, waits, and frame callbacks. Ambiguous positional bookkeeping does not gate ordinary manual commits: unsafe cursor/tail predictions and context-dependent assistance are discarded, while commits remain relative to the current connection and reset epoch. This does not grant additional destructive-repeat credit or confirm delivery; guarded mutations still require usable evidence.

`EditorSessionState` separates observed host selection/context from predicted local state, records composing bounds, and binds work to a connection and reset epoch. Its ordered edit ledger is bounded to 32 entries (forward typing can coalesce); overflow marks ambiguity rather than confirming delivery. `EditorTail` holds a bounded 96-UTF-16-unit suffix plus completeness, not a single expected cursor. Missing context or an exhausted partial suffix is not confirmed document start, and unknown selection remains unknown rather than becoming zero. Service callbacks forward old/new directed selection and composing bounds. Local ledger positions are bookkeeping, not Android acknowledgment IDs: compatible coalesced evidence can retire a unique prefix without rewinding prediction, while matching an old cursor alone cannot prove ownership. Android supplies neither tagged callbacks nor an atomic read/check/delete transaction.

`DeleteRepeatCoordinator` has `Idle`, `Running`, `AwaitingEvidence`, and `AtBoundary` phases. The dispatch window permits at most two unconfirmed character operations or one bounded word operation, blocks pending typing/word work and ambiguity, and stops granting credit once the oldest pending work exceeds 240ms. Context is acquired at the start or refreshed at context/credit boundaries, not queried on every trusted repeat. Refresh attempts are spaced by at least 80ms unless fresh progress resets the gate. Word deletion uses bounded trustworthy context; a partial word reaching the cached edge falls back to a character step. The view schedules one monotonic absolute deadline at a time and skips missed ticks instead of catching up in a deletion burst.

Transient stale/missing evidence retains pointer ownership while destructive dispatch waits; compatible evidence permits the same hold to resume without lift/repress. Unknown absolute metadata can fall back to readable bounded suffix evidence, but repeated/ambiguous suffixes cannot establish unique progress. Opaque or protected editors can exhaust the small evidence allowance; manual taps and the no-read policy remain, not a promise of universally uninterrupted holds. Null metadata responses remain retryable rather than being permanently classified as unsupported; otherwise a transient host failure would disable recovery. Release/cancellation, incompatible external edits, failed deletes, or replacement end the old hold; already submitted remote work cannot be recalled. Dictation, Live, Polish, paste, and cursor movement are manual-state handoff/invalidation boundaries. Start/restart, hide/unbind, finish, and view disposal cancel obsolete session work.

Pointer and haptic behavior is specified in [Keyboard feel settings](android-development.md#keyboard-feel-settings); diagnostic endpoints and the isolated host are described under [Current trace — debug-only, content-free](android-development.md#current-trace--debug-only-content-free). Actual measurements belong in [S24 Ultra testing](s24-ultra-testing.md), not inferred from these contracts.

## Deferred

Billing/accounts, production Redis integration, Play Integrity, RevenueCat webhooks, and iOS are gated after physical Android POC acceptance. iOS cannot provide an Android-style overlay or microphone-enabled custom keyboard.
