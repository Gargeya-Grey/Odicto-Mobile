# Android development

## Requirements

Install Android Studio, its JDK 21 runtime (required by Capacitor 7), Android SDK/platform 35, and platform tools. Open `apps/mobile/android` after running `npm run android:sync`.

## Activation test

Develop with the debug build; testers install the signed release APK from GitHub Releases. Run this checklist on the release APK before sharing a release. This checklist describes required checks, not passed results. Record actual evidence separately in [S24 Ultra testing](s24-ultra-testing.md); source changes and automated coverage alone do not establish that X insertion is fixed or physical interaction checks passed. Use synthetic content and never publish a test post. Verify visible output or an honest unverified/rejected state with Copy/history recovery, without automatic retries.

1. Install the APK under test on a physical device.
2. Grant microphone and notification permission.
3. Enable Odicto under system keyboard settings, then select it as the current keyboard.
4. Focus a normal text field. Confirm only the voice bar appears, then expand with the top-left keyboard button, type a sentence, and collapse again. Switch fields and verify the bar starts collapsed. Dictate with the keyboard microphone and the enabled floating microphone while both surfaces remain visible.
5. Test a space tap, hold/drag arming, small horizontal steps and immediate reversal over Unicode text. Vertical jitter must not jump to document edges; cancellation must insert nothing. Check exact key boundaries/gaps and the guarded uppercase hold choice.
6. Open emoji and clipboard panels and insert synthetic text. Exercise 51 distinct copies, pins, long exact paste, restart, clear, recopy, the capture disable switch, and sensitive/protected exclusions; clipboard content must never reach `logcat`.
7. Test a password field and a numeric field: typing works, while the microphone, emoji, and clipboard are refused with a visible reason.
8. Type a sentence without tapping Polish; verify no correction request is made. Set an OpenRouter key in Odicto settings, then tap the top-right Polish button in a normal field. Test selected-only and no-selection whole-field correction, unchanged surrounding text, reversed selections, proper names, cursor placement, and exactly one replacement. Exercise completed-result Copy/dismiss recovery and its 120-second expiry. Repeat while typing, moving the cursor, or switching fields during processing: the old field must not be overwritten. An unreadable/oversized field should show an in-keyboard refusal without sending text.
9. Check >=600dp usable-width split layouts, rotation, inert center gap, both space halves, mic/Polish adjacency, compact Copy/stop/cancel access, and actual navigation insets. Test haptic timing, TalkBack, and scaled fonts on a real device.
10. Open the bank app that previously warned about an overlay and record the result; the pause tile and in-app pause switch are the documented answer when it still warns.
11. Install the release APK from GitHub in a browser on a phone in India (or another market where enhanced fraud protection is live) with Play Protect on: it must install without the "access to sensitive data" block. With a keyboard other than Odicto active, the floating microphone stays dimmed and a press explains that voice types through the Odicto keyboard. Open the options row with a last result present: it folds away on its own after about eight seconds, and a touch on it keeps it open longer.
12. Light and dark: with the phone in dark mode and Appearance on System, Odicto is dark. The header button reads "Light"; tapping it grows the light theme from the button, the status-bar icons turn dark, the keyboard and floating microphone turn light, and the label becomes "Dark". Settings → Appearance → System follows the phone again. With a keyboard showing, flip the phone's dark mode (`adb shell cmd uimode night yes|no`): the keyboard rebuilds in the new theme and stays open. Check the expanded grid, the emoji and clipboard panels, the options row on the floating microphone, and the launch screen in both modes. Restore the phone's own setting afterwards. Never open the clipboard panel with real keys in its history while capturing screenshots.
13. Update card: install the previous release, publish (or stub) a newer one, and open Odicto. A card "Odicto X is available" appears at the top of Home within a few seconds, **Download** opens that release's page in the browser, and installing the new APK over the old one keeps keys and history. **Not now** hides the card until an even newer version exists. With **Settings → Updates → Check for updates** off, no card appears and no request is made. Offline, no card and no error appear.

**Update check.** `UpdateChecker` (package `app.odicto.mobile.update`, bridged by `UpdatePlugin` as `OdictoUpdate`) tells the user when a newer release exists. React reads what is already known at once (`status`), then asks for a check (`check`) when the app opens or returns to the front; the phone makes a real request at most once an hour after a success and at most once every 15 minutes after a failure (`UpdatePolicy`), and only while **Check for updates** is on (default on). Requests are conditional (`If-None-Match` with the list's `ETag`), so an unchanged list is answered with 304, which does not count against GitHub's 60-requests-an-hour anonymous limit; the tag is only remembered for a list that was understood. **Settings -> Updates -> Check now** forces a check past the hourly pause (never past the switch) and the row reports the result in words: latest, newer available, last checked when, or could not reach GitHub. A failed attempt is no longer silent: the snapshot carries `failed` and `checkedAt`. This replaced a once-a-day pause that hid a release published after the last check for up to a day. The request is an unauthenticated GET of `https://api.github.com/repos/Gargeya-Grey/Odicto-Mobile/releases?per_page=30`. The release _list_ is used because `/releases/latest` skips releases marked Pre-release, which all of them are so far. The highest non-draft tag of the exact form `vMAJOR.MINOR.PATCH` (`ReleaseVersion`) wins, so the release workflow must keep tagging `v<versionName>`; other tags are ignored. A newer version than the installed `versionName` shows the Home card; **Not now** stores that version and hides it until a higher one is published; turning the setting off hides any stored offer. **Download** opens `https://github.com/Gargeya-Grey/Odicto-Mobile/releases/tag/v<version>` in the browser. That URL is built from the validated version number, never from a link in the response, and the app never downloads or installs anything itself (Android's installer does, which only accepts an APK signed with the same key). The response is capped at 1 MB, times out after 10 seconds, and any failure leaves the screen unchanged. State lives in the `odicto-settings` DataStore (`update_check_enabled`, `update_latest`, `update_dismissed`, `update_checked_at`, `update_attempted_at`).

Test Android 12, 14, and the current Play target on Pixel, Samsung, and Xiaomi hardware. Exercise denied permissions, offline requests, timeouts, keyboard switching, screen lock, process death, restart, and OEM battery restrictions.

## Direct provider connections

Android voice calls Groq, Gemini, and OpenRouter directly over the phone's internet connection. Enter keys in Voice settings; they are stored using Android Keystore. No `npm run dev`, USB forwarding, or hosted Odicto API is needed for dictation. USB is only used to install/debug the APK. See [S24 Ultra testing](s24-ultra-testing.md).

The top-right IME Polish button uses the same device-encrypted OpenRouter key but has its own model and system prompt in the Text polish settings section. The default model is exactly `poolside/laguna-xs-2.1`; a missing/unavailable model or key shows an error without a fallback. On an explicit tap, it sends only the selected substring, or the whole field if nothing is selected. Both paths require a complete eligible field snapshot of at most 20,000 UTF-16 units; surrounding guard text stays local for selected-only requests. Partial or protected fields are refused. Replacement revalidates the editor and original target range; completed but unapplied/unverified output has transient 120-second Copy/dismiss recovery, not persistent Polish history or automatic retry. Ordinary typing makes no network correction request.

## Keyboard feel settings

`KeySettings` in `VoicePreferences` holds the keyboard's feel, and the React Settings page edits it through `VoicePlugin.save`:

- `autocorrectEnabled` is off by default. **Autocorrect (English)** in Keyboard settings enables local spelling choices, word completions and correction on Space. Immediate Backspace or the visible Undo button restores the original word and removes that space; the next Space preserves the original. Suggestions show only with the keyboard expanded, inside the fixed 48dp top row: three slots (the typed word to keep, the word Space applies in bold, one more choice) replace the tool cells between Undo and the mic. The slot lingers 1.6s between words so the tools do not flash, then returns them. Status messages temporarily replace choices while present. Lookup runs off the key-dispatch thread; previous candidates can remain briefly during the next lookup, but generation guards make them inert. Space applies a correction only when it is confident: "i" and contractions (dont, im), the reviewed typo table, or one plausible edit (transposition, neighbouring key, doubled letter) to a dictionary word with no close rival. Short words need a frequent target; Title-case words change only at a sentence start; slang, tech words and dictionary words never change. Picking a suggestion adds a space. The attributed bundled dictionary is in `assets/spelling/`. No typing is uploaded or learned. Protected and identifier fields do not get spelling assistance. Ordinary Search-action text fields honor the user's autocorrect setting even when the app requests no suggestions (as Google search does); other no-suggestions fields remain excluded. See the fixture's `autocorrect` and `autocorrectoff` scenarios for repeatable generated-text device checks.

- `hapticLevel` 0-3 maps to off, light, medium, and strong. `Haptics.prepare` caches vibrator capabilities, immutable effects, and touch attributes at view initialization. Playback synchronously requests a supported touch primitive (`PRIMITIVE_TICK` / `PRIMITIVE_CLICK`) or one-shot fallback, using `USAGE_TOUCH` where supported; there is no delayed feedback worker. API request/return timing does not measure physical motor onset. A store written before levels existed resolves through the old `haptics` boolean, so a user who turned haptics off does not get them back. Read it with `VoicePreferences.levelOf(...)`, never the raw field. Each dispatched backspace repeat requests configured feedback once; an evidence-wait tick requests none. Feedback does not confirm host deletion.
- `keySize` small/medium/large maps to 46/52/58dp row height and 15.4/17.6/19.8sp glyphs. Visible key margins stay at 2dp per side. Tap tolerance changes only the inactive inset within each key's allocated cell: Precise (0) keeps the 2dp inset, Balanced (1) reduces it to 1dp, and Forgiving (2, default) uses the full cell. Painted spacing never changes. Touch rectangles remain nonoverlapping and half-open (left/top inclusive, right/bottom exclusive); split gaps, blank slots, outer tablet insets and space outside the grid stay inert. There is no unbounded nearest-key fallback. The independent `voice_tap_tolerance` preference is bounded to 0..2; missing or malformed values use Forgiving and partial saves preserve omitted settings. The experimental visual-spacing preference does not control this setting. Appearance/tolerance changes rebuild the grid and cancel pending touches; unrelated preferences do not rebuild it. This changes software hit testing, not digitizer pressure/sensitivity, and cannot recover touches Android never delivers. The spacebar row is 1.2 times a letter row; Enter matches backspace width. The letters page has no period key.
- Typing dispatch remains on touch-down with synchronous configured haptics and multitouch. Ordinary letters commit immediately, without a frame-spanning batch or per-letter selection query; compound replacements use short balanced operation-scoped batches. Session-observed/predicted state and a bounded edit ledger replace single-expected-cursor tracking; see [Manual input continuity](architecture.md#manual-input-continuity) for evidence and repeat bounds. A 300ms letter hold switches the pressed-key preview to the capital letter and highlights the uppercase choice inside the IME; release on it accepts, moving away cancels. Replacement is guarded by the actual committed character/range, editor identity, and text/selection generations, never unconditional backspace; already auto-capitalized letters are not duplicated. Secondary typing, geometry/page changes, focus loss, and cancellation invalidate the choice. Shift/caps lock and an accessible uppercase action remain available.
- Space cursor mode arms after a 250ms hold or approximately 8dp horizontal travel. Activation travel is consumed; subsequent 4dp signed steps move by grapheme with fractional remainder and immediate reversal, rather than waiting to retrace the previous excursion. Each accepted grapheme selection requests configured synchronous haptics; boundaries, rejected writes, and haptics-off produce no movement pulse. Coalesced motion is submitted as individual steps without a delayed feedback queue; physical pulse separation and latency still require device acceptance. Cursor reads and writes revalidate the current editor epoch and connection. Vertical motion never jumps to document edges. A tap inserts one space on release; cancelled/armed gestures insert none. Session-local cursor prediction is invalidated on editor/text/external selection changes. Gestures remain disabled during voice/AI selection work.
- Holding comma offers punctuation and sliding onto a choice replaces the comma. Enter follows the editor's Search/Go/Send/Next/Done/newline action. Double-tap Shift locks capitals; sentence capitalization and double-space period remain. Held backspace enters the word phase after ten steps when context permits. Transient evidence gaps suspend destructive dispatch and allow the same hold to resume; opaque/ambiguous hosts may exhaust the bounded allowance. Primary/secondary pressed states have separate lifecycles; backspace repeat belongs to its initiating pointer and primary space gestures stay with their owner. Secondary cleanup precedes pointer assignment. Owner release/cancellation ends the hold rather than transferring it to the other thumb. Prefix predictions remain hidden; optional spelling replacements use the fixed-height strip described above.
- `keyFont` is `system` or `instrument`. Instrument Sans, the face of the app screens and the EduDojo website, is the default key face, bundled in `assets/fonts/InstrumentSans.ttf` from `google/fonts` under the SIL Open Font License 1.1, with `assets/fonts/InstrumentSans-OFL.txt` shipped alongside. Stored `sansflex` and `lora` values from earlier faces are read as Instrument Sans; only a recorded `system` choice stays on the system face (`KeySettings.resolveFont`). An unreadable font falls back to the system sans and must never crash the keyboard.
- `pinnedEmoji` is the favourites row, stored comma-joined, capped at five, re-validated on load. Toggle it with `VoicePreferences.withPinned(...)`.

The IME opens in voice-first mode: the key grid and bottom tools stay hidden until the top-left keyboard toggle is tapped. The IME window keeps the expanded height in both states; collapsed, the column is translated down so only the top row shows, and `onComputeInsets` reports the visible top and a touchable region so the host app keeps only that part clear and receives touches above it. Expand (300ms, system IME curve) and collapse (220ms, accelerate) are a `translationY` of the column and honor the system animation setting; no frame resizes the IME window or relayouts the host app. The host app is resized once: before an expand, and after a collapse. Reversing mid-animation continues from the current reveal; hiding the window or focusing a new editor resets to the voice bar. Nine fixed allocations fit the toggle, Undo, settings/cancel, Raw, AI, Live, lock/Copy, mic, and Polish. Their widths adapt from 32dp at the supported 288dp minimum to 48dp at 432dp and above; height remains 48dp.

Undo sits between the toggle and the voice cells and is never covered by suggestions or status. It reverses the last verified Polish: `FieldPolishCoordinator` retains up to three applied replacements in memory (complete before/after field text, the replaced range, and the original selection), drops them when the editor finishes, and persists nothing. At the tap it re-reads the whole field. The text up to the end of the polished range must be exactly what Polish wrote, and text typed after the range is kept. Any other change refuses with "Text changed since polish" and spends the entry. A write that is not confirmed is never retried. It is dimmed when there is nothing to undo, and answers taps with a notice instead of hiding. Undo does not cover voice insertions.

**Press and motion.** Controls outside the key grid share one press system (`PressSurface`). A pressed control shows a soft rounded tile that fades in over 80ms and out over 250ms on the smooth-out curve, with no spreading ripple circle; icon buttons cap the tile to 56dp so it hugs the icon, and a selected control (the keyboard toggle) keeps a quiet fill. Icon-style controls also press in to 0.9 and spring back with a small overshoot (`animator/odicto_press`); wide surfaces (the paste pill, emoji category pills) press in to 0.97 only. The key grid keeps its colour-only press on purpose, because a scale animation read as lag between finger and key. Timings and curves are taken from the transitions.dev token scale: `smooth-out` cubic-bezier(0.22, 1, 0.36, 1), a gentle bounce (0.34, 1.36, 0.64, 1), 80ms/150ms/250ms durations. Three of its recipes are used directly: _tabs sliding_ (the jade chip behind Raw/AI/Live in the keyboard header glides to the new mode over 250ms), _icon swap_ (the keyboard toggle's glyph dips out and the new one settles in), and _toast_ (the paste pill rises 6dp, fades and settles from 0.97 over 250ms). All of it follows the system animation setting, so with animations off every change is instant. The cursor-drag chevrons flank the grip on every space bar, in the grid as well as the quick row.

The **paste suggestion** is a small pill in the header's centre slot (`ime_paste`, covering the same cells as the status and spelling slot, and yielding to any status message) offering the just-copied text for one tap. `PasteSuggestion` holds one offer for 30 seconds from the clip's own timestamp, so a copy made where no text field is focused still counts when you next focus one. Each clipboard sample the capture gate already allows becomes an offer (see [Privacy and security](privacy-and-security.md#local-clipboard-and-editor-reads) for what it shows and masks). It stays across app and field changes, hides in fields that refuse clipboard text and during voice, Polish and status messages, and is spent for that copy by pasting, the pill's dismiss button, typing on either key view, opening the typing area, speaking, Polish or Undo. A new copy is offered again.

The **quick-edit row** is a second, always-visible 48dp header row (`ime_quick_keys`) holding comma, period, space, backspace and enter. It is a second instance of `OdictoKeyboardView` in `Page.QUICK` mode: one fixed row, never split, same hit-testing, haptics, cursor-drag space, repeating/word backspace and hold-for-punctuation on comma and period (the strip draws over the row, since nothing sits above it). `KeyboardController` wires both views to the same handlers, so every editor-safety rule applies identically. Enter follows the field's action exactly as the grid's Enter does and turns into a jade Send/Go/Search/Next/Done key whenever the field asks for an action; in plain or multiline fields it stays a newline. Because it belongs to the header, it stays on screen with the typing area collapsed. Expanded, it would only repeat the grid's own bottom row, so it is squeezed away: the typing area slides up over it while it shrinks (`scaleY` about its top edge) and fades faster than it shrinks, and the column settles lower by the row's height. This is translation, scale and alpha only, driven by two fractions in `KeyboardExpansion` (reveal of the typing area, squeeze of the row), so the IME window keeps one height and the host app hears one inset change per transition. The visible expanded keyboard is exactly the row's height shorter than the collapsed header plus the typing area. Polish recovery reveals the typing area without expanding, so the row stays. Collapsing reverses it, continuing from the current frame when reversed mid-motion. Empty slots have no touch or accessibility target; busy/result/meter changes do not move persistent controls. The enabled floating microphone stays available alongside both collapsed and expanded IME views, sharing the existing VoiceSession. Its position is temporarily clamped above the IME with an 8dp gap, without changing the stored drag anchor. When a tall overlay card cannot fit, its controls use a 72dp row and the IME retains the status message. If even that row cannot fit, the keyboard microphone remains available and the bubble returns when space is available. A horizontal drag preserves the preferred vertical anchor.

The status and recovery descriptions below are implementation contracts, not a physical-device acceptance result. See [the bounded status verification handoff](s24-ultra-testing.md#keyboard-status-fix-bounded-verification-handoff) for the installation gate and outstanding checks. Do not reinstall a candidate after a failed full Gradle run until that failure is resolved.

Status uses one font-scale-aware line with end ellipsis and normalized newlines. It shares the fixed 48dp top row with suggestions and covers tool cells instead of adding a row: idle, the cells between Undo and the mic; during voice, only the Raw/AI/Live cells, so cancel, lock and the mic stay where they are. It is not clickable or expandable. Busy messages persist until the operation ends; terminal messages and explicit Copy feedback clear after three seconds, extended by Android's recommended accessibility timeout. Complete current warnings remain in the visible status accessibility description. Expiry hides only IME presentation: retained voice results and explicit Copy remain available, and neither delivery nor history persistence is inferred from message expiry. Meter/history updates do not renew deadlines; hiding/recreating the keyboard cancels view callbacks without replaying expired results. Copy rechecks eligible editor policy at the tap.

Polish Copy/Dismiss/countdown replaces the existing content slot rather than adding a row below the header. Dismiss returns to typing; copying or its unchanged 120-second expiry also closes recovery. Countdown ticks do not resize the keyboard or announce every second. The bottom tools retain actual navigation-bar insets instead of the old fixed 18dp margin. The keyboard status layout is independent of the floating overlay. Overlay terminal chrome now collapses to the 72dp mic after three seconds (extended for accessibility), without discarding recovery text. Back also only collapses; double tap or the accessibility options action reopens mode controls and Copy for Raw, AI, and Live results. History/meter updates do not renew the deadline, and hiding/recreating the view does not replay an expired result. Copy rechecks the current eligible field at the tap; clipboard failure retains the result. Mic anchor placement, recording gestures, and the Copy toast remain unchanged.

Split geometry uses the measured keyboard width after padding and the current orientation. Portrait uses `clamp(width - 600dp, 0, 64dp)` for a modest center gap; landscape uses `clamp(width - 576dp, 0, 375dp)`, retaining the roomy 375dp gap only when it leaves at least a 48dp column pitch. Gaps below 16dp are suppressed. Both split orientations reserve equal outer thumb insets of one sixth of each half's available width, plus pixel-rounding remainder. This keeps tablet portrait keys away from the gripping edges without adding insets to narrow, unsplit phone layouts. Both halves share five columns: character and unit-control widths match, unequal key counts leave inert slots instead of stretching keys, and both spacebars have equal allocations. Enter and Backspace align without borrowing width from the right Space. All existing outputs and their order remain available on every page.

Narrow windows use the unsplit docked layout. The one-handed and floating modes and their layout key were removed: the key sat under the spacebar, and a near miss moved the whole keyboard. Width, padding, density, or orientation changes recompute geometry and cancel active touches, cursor gestures, uppercase choices, and repeats; even a same-width rotation invalidates geometry. Fullscreen extract mode remains disabled. Actual thumb reach still requires physical acceptance; see the tablet verification entry in [S24 Ultra checks](s24-ultra-testing.md).

Panels replace the key grid, never stack below it outside the IME window. Emoji uses nine categories with 608 local choices, a 32-choice default grid, and vertical scrolling; category tabs stay visible and repeated insertion keeps the same category and scroll position. The 123 page includes straight double quotes, apostrophe, common punctuation, brackets and operators; the next symbol page adds braces, backslash, typographic quotes and existing currency/bullet/arrow choices. Completed Polish recovery temporarily reveals its own panel if typing was collapsed, then restores the voice bar when dismissed or expired. Clipboard rendering uses saved state, not a platform clipboard read: the panel discloses gated automatic local capture and offers a disable switch, 50 recent unpinned items, persistent pins, selection/delete, and Clear all unpinned. See [Privacy and security](privacy-and-security.md#local-clipboard-and-editor-reads) for exact-text storage, migration limitations, and capture eligibility.

## Current trace — debug-only, content-free

The input core and probes must be judged by the replay and physical results recorded in [S24 Ultra testing](s24-ultra-testing.md), not by API timing alone. The isolated host includes a transient-read profile that reproduces and checks recovery from the earlier held-backspace stop.

`KeyLatencyProbe` keeps a bounded 1,024-sample ring and exports count/p50/p95/p99/max off the input hot path, including short trials on keyboard hide. It records event-queue/handler/hit timing, haptic preparation/request/API duration, instrumented character submission/return, cursor API duration, and repeat lateness. Event uptime is explicitly converted relative to handler-entry elapsed time; touch-to-* samples start at handler entry, not physical finger contact. A metric declaration alone does not establish coverage: the batch-close hook is not a host-frame marker, and read/depth/suspension metrics must not be assumed present in the IME trace. Samples contain local event IDs and timings, never text, key values/labels, clipboard payloads, prompts, or credentials.

Use the standalone permissionless `tools/keyboard-interaction-host/` (`app.odicto.keyboardtrial`) for isolated generated-text trials: native single-/multiline fields, switching, restart/recreate, Unicode samples, and host-only instrumentation across the real IME process boundary. It requests no permissions, stores no text/credentials, and disables backup. Keep trials out of personal notes/conversations; never clear/uninstall personal Odicto or inspect saved keys.

Measurement bounds are separate: **IME API return ≠ host text application ≠ host draw ≠ screen presentation**. The host's `apply` series times wrapped editor-method execution; text-watcher changes establish local mutation, deletion intervals measure mutation gaps, and `changeToDraw` spans the first pending change to the next active editor `onDraw`, potentially coalescing changes. Batch depth/lifetime and Choreographer frame opportunities are not presentation evidence or end-to-end event correlation. Haptic API timing is not physical vibration onset. Report presentation and motor onset as unmeasured without independent instrumentation; distributions alone do not prove improved feel or a fixed stall.

## What ships in the APK

There is a single build — no product flavors. `app.odicto.mobile` ships the IME, the microphone capture service, the floating overlay with its `specialUse` foreground service, and the Quick Settings pause tile. It ships no accessibility service. The bubble requires the Android display-over-other-apps permission. `BuildCapability.overlaySupported` is `true`; shared code must still consult it instead of assuming the overlay exists, and `VoiceOverlayController` returns without starting anything when a future build flips it off.

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

**Why no accessibility service.** Google Play Protect's enhanced fraud protection blocks the install of an APK that comes from a browser, messaging app or file manager when it declares `BIND_ACCESSIBILITY_SERVICE`, `RECEIVE_SMS`, `READ_SMS` or the notification-listener permission (live in India, Singapore, Thailand, Brazil and Malaysia; message: "This app can request access to sensitive data"). ADB installs skip the check, so a debug install never shows it; verify with the release APK downloaded in a browser, Play Protect on. The only insertion channel is the Odicto IME, so the floating microphone dictates only while Odicto is the active keyboard. Pausing (the in-app switch or `PauseTileService` in the shade) stops the overlay and resuming brings it back. After a reboot or app update the overlay returns when the app opens or the Odicto keyboard next starts input in a field.

`VoiceOverlayService` runs as a `specialUse` foreground service while the bubble is enabled, so OEM freezers cannot suspend the process behind an unresponsive overlay. It stops itself when the bubble is disabled, paused, or the overlay permission is missing; the persistent notification is minimal importance and opens the app when tapped.

## Play readiness

- Play distribution is not current. The build ships no AccessibilityService, so a future Play release would not need that declaration; the `specialUse` overlay still needs its disclosure.
- Still required before an upload: the data safety form (microphone, network processing by the selected AI providers, device-only history, optional BYOK), the `FOREGROUND_SERVICE_MICROPHONE` and `FOREGROUND_SERVICE_SPECIAL_USE` declarations, and a target API check. The project targets 35 and the test device runs Android 16 (API 36).
- The pause control exists because banks and other protected apps refuse to run with an overlay drawn. It is not a way to bypass those checks and should never be described as one.
